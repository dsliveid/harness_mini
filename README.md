# harness_mini

轻量 AI Agent 编码工具（Tauri 2 + React + Rust）。完整需求与设计见 [需求说明文档.md](./需求说明文档.md)。

## 功能（第一期）

- **对话**：OpenAI 兼容模型流式对话（GLM / DeepSeek / OpenAI / Ollama 等），Markdown + 代码高亮，随时停止。支持配置多个厂商，同一厂商可配多个模型；顶栏模型选择按厂商分组切换。
- **Agent 编码能力**：读/写/编辑文件（diff 呈现）、执行命令（实时输出）、glob/grep 搜索、todo 任务清单。
- **审批与访问模式**：只读自动放行；写入与命令默认审批（允许一次 / 本会话允许 / 拒绝并说明原因）；高危命令强制逐次确认。顶栏可切换 **变更前确认 / 完全访问**，切换即时生效（对话进行中同样立即生效）。
- **访问模式为会话级**：每个对话独立保存自己的模式，互不影响；新建对话默认继承「上一条对话」（当前选中的对话）的模式与工作区；设置页的「新对话默认访问模式」仅作为无可继承来源时的默认值。
- **审批规则（会话级）**：审批时选「本会话允许」记下的规则仅对当前对话生效并持久化，不跨对话共享、不继承；可在侧栏会话「…」→「会话设置」中查看与删除。
- **运行中补充输入**：运行中继续输入会进入输入框上方**待执行列表**，可「引导」（立即介入当前对话）或「删除」；未引导的在当前对话结束后自动依次执行。
- **编辑重发**：悬停最后一条用户消息可编辑并重新发送（其后消息作废，重新运行）。
- **会话管理**：列表 / 项目双视图、项目分组与置顶、按最后对话时间倒序、归档中心（查看 / 取消归档 / 删除）、临时对话（首条消息发送后才落库）。
- **工作区即项目**：顶栏选择工作区 = 选择项目，提供三个选项——已有项目 / 选择目录 / 不选择（纯对话）；会话保存时按工作区路径自动归入对应项目，项目不存在则自动创建（项目名取目录名）。
- **项目设置（项目约束 / 关联项目）**：侧栏项目「…」菜单进入。项目约束支持 Markdown 编辑与预览，该项目下每个新对话自动注入系统提示词（同一对话不重复注入、上下文截断不丢失、修改后下一条消息生效）；关联项目可选择目录并撰写说明，对方项目自身已设约束时一并注入，与本项目约束冲突时以关联项目为准。
- **临时空间（需本机安装 Git）**：项目行的 🌪 按钮或「…」菜单发起临时空间对话。点击即生成唯一随机码目录计划（`数据目录\temp-project\<随机码>\`，此时不创建目录）；发送首条消息后检查并按需把主项目与关联项目拷贝进去（排除 `.git` / `node_modules` / `target` / `dist` 及 .gitignore 命中文件），并在每个副本内自动提交一次基线。对话工作区绑定为主项目的临时副本（沙箱覆盖整个临时空间），原目录不受影响；系统提示词注入临时空间说明——优先级 **临时空间 > 关联项目 > 项目约束**，且空间内改完代码只需静态检查、无需编译运行。侧栏临时对话带「临时」标记，对话框上方悬浮「变更 / 临时目录 / 合并 / 清空空间」按钮：「变更」弹窗左侧按项目分组展示变更文件（文件名、路径、±行数），右侧展示变更点并支持统一视图与并排对比（变更前 | 变更后），无变更时按钮禁用；「合并」把相对基线的变更写回原目录（原目录又被改过的文件由 AI 智能合并），合并后对话禁止发送、合并点前消息永久不可编辑，清空空间后可继续（空间按需重建）；临时空间仍存在时删除/归档对话会被拦截。项目「…」菜单与顶栏工作区选择器旁提供「打开目录」。
- **系统托盘**：点击窗口关闭默认隐藏到系统托盘继续运行（后台对话不中断）；左键托盘图标显示主窗口，右键菜单可显示 / 退出程序。
- **纯对话模式**：不选择工作区也可直接对话（文件 / 命令工具不可用）；顶栏可随时绑定工作区，已绑定时可一键清除转为纯对话。
- **本地优先（便携式存储）**：全部数据存本地 SQLite；API Key 以 AES-256-GCM 加密存库（主密钥为数据目录下的 `secret.key`）。数据默认存放在**程序同级 `data\` 目录**，不写用户目录，拷贝程序目录即可整体迁移（含全部会话与 API Key）；仅当用户在设置中显式选择自定义数据目录时，才在 AppData 写入一个 `data_dir.txt` 指针文件。程序目录不可写时（如放入 Program Files），启动时会提示选择其他数据目录或迁移程序。

## 开发

```bash
npm install        # 安装前端依赖
npm run tauri dev  # 开发模式（Rust 首次编译较久）
```

或用便捷脚本（自动检查 Node / Rust 环境、按需安装前端依赖）：

```bash
./run.sh                # 启动开发模式（Windows：run.cmd）
./run.sh --skip-install # 跳过依赖检查
./run.sh --dry-run      # 只检查环境并打印将要执行的命令，不真正启动
./run.sh --no-pause     # 失败后不等待回车，立即退出
```

### 多实例开发（端口顺延）

- 默认 dev 端口 5601 被占用时（如已开着另一份实例），vite 会自动 +1 顺延；实际端口由
  `scripts/tauri-dev.mjs` 从 vite 输出解析后覆盖到 `tauri dev --config` 的 devUrl，两个实例完全独立。
- 经 `npm run tauri dev` / `run.cmd` / `run.sh` 启动即自动生效，无需任何配置。
- 请勿绕过包装器直接 `npx tauri dev`：CLI 读不到顺延后的端口，第二实例会挂到第一实例的 vite 上。
- 同一工作区内多开受 cargo 产物锁限制（旧实例运行中时无法重链接 `harness-mini.exe`），
  多目录副本各自独立 target，无此限制。

## 构建安装包

```bash
npm run tauri build
# 产物：src-tauri/target/release/harness-mini.exe
# 安装包：src-tauri/target/release/bundle/nsis/*.exe
```

或用便捷脚本（构建结束后自动列出产物路径与体积）：

```bash
./build.sh                # release 可执行文件 + NSIS 安装包（Windows：build.cmd）
./build.sh --no-bundle    # 只编译可执行文件，不生成安装包
./build.sh --debug        # debug 构建，仅用于验证
./build.sh --clean        # 构建前 cargo clean（全量重编译）
./build.sh --dry-run      # 只检查环境并打印将要执行的命令，不真正构建
./build.sh --no-pause     # 失败后不等待回车，立即退出
```

两个脚本用 bash 编写，可在 Git Bash、Linux、macOS 直接运行。Windows 上 Git Bash 若不在 PATH，
直接运行 `run.cmd` / `build.cmd` 即可：包装器会自动定位 Git Bash（PATH → 由 `git.exe` 位置反推 →
常见安装目录），并临时把控制台切到 UTF-8 代码页以保证中文输出正常。

### 失败不被窗口“吞掉”

脚本失败时不会立即退出：先打印退出码，再提示**“按回车键关闭窗口”**，等待回车后才退出，
因此双击启动也能看清报错而不会被窗口一闪而过。退出码原样保留，可直接用于脚本/CI 判断。

判断依据只有一个：**stdin 是不是终端**（`[ -t 0 ]`）。

- 双击 `run.cmd` / `build.cmd`，或直接在 Git Bash 里运行 → stdin 是终端，失败时暂停。
- CI、输出被重定向、IDE/工具宿主（stdin 不是终端）→ **不暂停**，避免流水线卡在等待输入。
- 退出码 0（正常结束、`--help`）不暂停。
- 用 `--no-pause` 可关闭暂停。

> 注意：不要去掉这个 `[ -t 0 ]` 判断。在 IDE/工具宿主里 stdin 不是终端，但 `read` 仍会一直
> 阻塞（已实测），去掉后脚本会挂死而不是报错退出。

要求：Node 18+、Rust 1.75+、Windows 10/11（WebView2 随系统分发）。

## 目录结构

```
src/          # React 前端（UI 层，无业务逻辑）
src-tauri/    # Rust 核心（Agent 运行时 / 工具系统 / 存储 / LLM 客户端）
  src/agent.rs      # Agent 主循环（轮次边界注入引导消息、队列串行消费）
  src/tools.rs      # 工具注册表与实现（风险分级、高危命令检测）
  src/approval.rs   # 审批决策（访问模式 → 规则 → 风险级 → 询问用户）
  src/llm.rs        # OpenAI 兼容 SSE 流式客户端
  src/store.rs      # SQLite（sessions/messages/tool_events/runs/projects…）
  src/paths.rs      # 数据目录解析（exe 同级 data\）、可写探测、旧库迁移
  src/secrets.rs    # API Key 加密（AES-256-GCM，主密钥 secret.key）
```

**数据存放位置**：release 版数据位于 exe 同级 `data\`（`harness_mini.db` + `secret.key`）；开发模式位于项目根目录 `.dev-data\`（避开 tauri dev 的文件监视，否则 SQLite WAL 文件变更会触发无限重编译，同时也不受 cargo clean 影响）。旧版本存放在 AppData 的数据库会在升级后首次启动时自动迁移（原目录保留为备份）。

架构上已为二期（定时任务）、三期（多任务协调）预留：会话为并发一等公民、Run 记录含 trigger_type、UI 仅为事件总线订阅者。
