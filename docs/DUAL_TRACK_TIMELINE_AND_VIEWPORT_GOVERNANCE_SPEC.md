## 一、问题背景与现象还原

在 AI Agent 执行过程中，用户反馈了以下典型故障：

1. **现象 A：对话结束后，页面只显示“执行清单”，最终的分析或回复结果未显示**
   - Agent 经历了一系列工具执行（如 `exec_command`、`view_file` 等），并在最后一步给出了详尽的总结文本；
   - 用户界面的对话流中仅能看到展开或收起的执行步骤清单，最后一条答复内容完全没有作为消息卡片呈现，必须刷新页面或用户重新聚焦才可能显现，甚至彻底被吞没。
2. **现象 B：用户在工具执行过程中看到内容形态突变**
   - 正在执行时，最后一步思考和输出塞在清单里或闪烁跳动；
   - 任务完结的瞬间，UI 进行 DOM 重树挂载，导致视图闪烁跳动，滚动条丢失。
3. **现象 C：长流程执行完结时视图停留在上方，用户误以为卡死**
   - 执行清单包含几十项步骤，当最后输出生成时，视口停留在上方的执行清单区域，未能自动带用户滚到底部查看最终结论。

## 二、底层机制与根因剖析

### 2.1 状态变异反模式（Mode Morphing Anti-Pattern）

在重构前，前端 `groupTimelineItems` 采用了一套“运行态”与“完结态”彻底分化的猜测逻辑：
- 当 `isCurrentRunningTurn === true` 时，系统将当前轮次的所有 assistant 步骤**全部塞入** `ExecutionProcessBlock.steps` 中，企图在执行清单的头部或尾部以小字体呈现当前步骤的 content；
- 当 `isCurrentRunningTurn === false` 时，系统才启动完结提取逻辑，试图将最后一条无工具调用的消息从 steps 中剥离，转化为外部的 `type: "message"`。

**致命弊端**：
1. **渲染容器动态变异**：同一个内容节点，在运行态挂载于 `ExecutionProcessBlock` 内部，在完结态被突然移出并挂载到外部独立卡片。这种容器跨级迁移极易破坏 React 的虚拟 DOM 状态（Diff 闪烁与重新挂载）；
2. **状态切换时隙吞没**：当长任务完成、后端推送最后一包消息时，若 `running` 状态在 SSE 结束或状态机流转中存在任何时延或边界情况，UI 将一直保持在“运行态处理逻辑”中，导致最终的交付回复被锁死在执行清单的抽屉内部，无法外显。

### 2.2 分支堆叠与认知复杂度爆炸

历史代码中，`groupTimelineItems` 累积了近 200 行复杂的 `if-else` 分支，试图覆盖：
- 场景 1：运行态单步普通流式
- 场景 2：运行态工具执行中
- 场景 3：运行态意图门控中
- 场景 4：完结态单步工具
- 场景 5：完结态门控卡片
- 场景 6：完结态单步思考+正文
- 场景 7：完结态纯单步文本
- 场景 8：完结态多步交付
- 场景 9：完结态多步中断

每当出现一个新的交互 corner case，便在分支树上追加一个补丁，最终导致分支相互遮蔽、逻辑不可理喻。

### 2.3 视口滚屏脱钩与视觉假死

在 `ChatView.tsx` 中，历史的 `scrollToBottom` 仅在 `streamingContent` 变化时以 120ms 节流触发。
然而，当 Agent 步骤长、生成最终总结答复时，DOM 高度急剧拉长。一旦用户曾在执行过程中发生过轻微的触控/滚轮微调，`isNearBottomRef` 就变为 `false`，滚屏跟随彻底失效。最终导致用户屏幕停留在巨大的执行清单中段，完全看不到下方已经生成的最终结果。

## 四、完整治理与工程落地实施方案

### 4.1 前端聚合算法重构：双轨恒定容器模型

彻底废除以 `isCurrentRunningTurn` 为顶层判断条件的模式，确立**“过程归过程轨，答复归交付轨”**的恒定单向聚合管线：

1. **角色判定**：检查轮次中最后一条 assistant 消息 `lastMsg` 是否包含工具调用 (`!hasAnyTools(lastMsg)`)：
   - 若不包含工具调用，则确立为**最终交付物（Deliverable）**；
   - 若包含工具调用，说明当前 Agent 正停留在工具执行阶段或执行被中断。
2. **过程轨 (Execution Track)**：
   - 提取除最后一条交付消息之外的所有前序步骤（以及最后一条中产生的思考过程 `reasoning`）；
   - 若前序步骤非空或存在意图门控卡片，则生成统一的 `type: "process"` 卡片；
   - 其运行态标记为：工具执行阶段已完毕时为 `false`（抽屉进入已完成稳态），工具仍在执行中时为 `isCurrentRunningTurn`。
3. **交付轨 (Deliverable Track)**：
   - 只要 `lastMsg` 是最终交付物，无论当前是否处于流式生成（`isCurrentRunningTurn` 为真或假），正文都**无条件直接发射为外部独立的 `type: "message"` 卡片**！
   - 杜绝一切“正文被塞入清单抽屉”的逻辑可能。

### 4.2 交付物净化与流式保护 (`cleanDeliverableContent`)

修复了 `cleanDeliverableContent` 在流式接收过程中的激进正则截断问题，确保正在吐字的 Markdown 块能够原样实时透传给渲染器，完结时才进行尾部空白收敛。

### 4.3 智能视口贴底与“回底药丸”交互优化

在 [`ChatView.tsx`](file:///d:/WorkSpace/Project/harness_mini/src/components/ChatView.tsx) 中引入三级滚动保障机制：
1. **状态流转触底锚定 (`wasRunningRef`)**：
   - 侦听 `running` 状态从 `true` 迁移到 `false` 的瞬时边界（任务完结瞬间）；
   - 无视微小滚动偏移，立即执行一次平滑触底校准，确保用户视野第一时间切换到最终结论。
2. **提问初始强制贴底 (`prevLastUserRef`)**：
   - 当用户发出新一轮提问时，重置用户滚动介入标记，强制平滑贴底。
3. **悬浮式“跳转到最新答复 ↓”快捷药丸**：
   - 当用户在长任务执行期间向上翻阅前序工具清单导致脱钩时，右下角优雅弹出半透明的浮动药丸按钮；
   - 用户只需点击一次即可平滑重回最新答复底部。
